How this was measured
---------------------
"Before the change" no longer exists in the working tree, so it was rebuilt rather than
simulated:

    git worktree add /tmp/op-base 74c6ed2
    git -c protocol.file.allow=always -C /tmp/op-base submodule update --init --recursive
    cmake -B build -DROCM_PATH=/opt/rocm-7.2.0 -DCMAKE_HIP_ARCHITECTURES=gfx90a \
      -DTRITON_LLVM=/home1/rvanoo/repos/triton/llvm-project/build \
      -DINTERCEPTOR_BUILD_TESTING=ON -DCMAKE_INSTALL_PREFIX=/tmp/op-base/install
    cmake --build build -j 48
    source <repo>/.untracked/test-env.sh   # exports TRITON_DIR + both INSTRUMENTED_* vars here
    bash tests/run_all_tests.sh

The submodule commits are byte-identical at 74c6ed2 and at HEAD (0c8a3635, 5bec9466), and
`git diff 74c6ed2 HEAD -- tests/rocblas_filter tests/hipblaslt` is empty, so the three
pre-built rocBLAS/hipBLASLt fixture binaries — untracked host programs that call the BLAS
libraries and contain no Omniprobe code — were copied into the worktree rather than rebuilt.
Without them the first attempt reported 3 suites failed on `test_rocblas_scal not found`,
which is a missing fixture and not a property of the commit. That run is discarded.

This is deliberately NOT the reconstruction the handoff proposed (force `app_loads_object`
false, rebuild in place). That would have reverted only half the change and would still have
run the four suites this packet itself adds, which did not exist at 74c6ed2.

Two beliefs that measurement produced, both now corrected
---------------------------------------------------------
1. The Handler-tests failure was recorded here as a PRE-EXISTING DEFECT, out of scope, and
   this file instructed the executor not to fix it. It is not a defect. The suite ran a gfx90a
   binary on a gfx950 GPU, where it silently fails to dispatch. On matching hardware it passes
   at 74c6ed2, before any change.
2. A project-level risk on record said the rocBLAS integration test was broken — "instrumented
   sscal not found in current build" — and this packet treated it as the main thing that could
   block AC-4 on a gfx90a node. It passes, at 74c6ed2 and at HEAD. `Found instrumented
   alternative for sscal kernel`.

Neither correction was available from the gfx950 measurement, because on that node four of the
six suites never ran. That is the lesson worth keeping: a baseline taken where most of the
suite skips records the environment, not the code.
